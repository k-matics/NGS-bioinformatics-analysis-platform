## 1. The overall workflow (germline WES)

```
FASTQ R1 + R2 ──► intake validation ──► FastQC ──► fastp trimming ──► BWA-MEM alignment (GRCh38)
   ──► fixmate + sort ──► duplicate marking ──► index ──► BAM QC (flagstat/stats/mosdepth)
   ──► variant calling (bcftools / GATK HC / FreeBayes / DeepVariant) on padded targets
   ──► bcftools norm (left-align, split multi-allelics) ──► soft filtering (per caller) ──► VCF ──► comparison
```

## 2. Why intake validation comes first

In a clinical pipeline the cheapest error to catch is the one caught *before* six hours of compute.
The **Sample intake validation** workflow answers four questions for every input file:

| Question | How | Why it matters |
|---|---|---|
| Is this exactly the file we think it is? | SHA-256 checksum, stored in the DB and in `checksums.sha256` | Later results are tied to an exact input. If a file is re-delivered or modified, the checksum changes and the platform refuses to resume old runs on it. |
| Is the FASTQ complete? | `pigz -t` decompresses the *whole* file and checks the gzip CRC | Truncated transfers are common (network copies, full disks). A truncated R2 makes R1/R2 lose sync and the aligner may fail — or worse, silently mis-pair reads. |
| Is the FASTQ well-formed and are R1/R2 paired? | First 100,000 records: 4-line structure, SEQ/QUAL lengths equal, Phred+33 encoding, identical read names in R1 and R2 | Read *i* in R1 must be the mate of read *i* in R2; the aligner relies on this order. |
| Is the BAM/VCF on our genome build? | Compare `@SQ` (BAM) / `##contig` (VCF) names **and lengths** with our reference `.fai` | Names alone are not enough (hg19 and hg38 both use `chr1`); lengths differ between builds (chr1: GRCh37 249,250,621 vs GRCh38 248,956,422). |

### How to read the build verdicts

| Verdict | Meaning | What to do |
|---|---|---|
| `identical` | Same contigs, same lengths | Fully comparable. |
| `compatible` | Every contig in the file exists in our reference | Comparable. |
| `primary_compatible` | Chromosomes 1–22, X, Y, M match, but the file has extra contigs (decoys, HLA, spike-ins) | Comparable on the main chromosomes; expect some differences near regions with decoy/HLA homology. |
| `incompatible` | Different build or naming | **Do not compare directly.** Re-align the FASTQ (preferred) or lift over. |

**Your test data, as found in Phase 2:**

* `SAMPLE_A/SAMPLE_A_provider.bam` (external, DRAGEN 4.3): `primary_compatible`. Its reference has 3,366
  contigs; 2,911 of them (decoys, HLA alleles, EBV) are not in our hg38.fa.
* `SAMPLE_B/SAMPLE_B_provider.bam` (external, DRAGEN): **`incompatible` — GRCh37** (`hg19_hs37d5`).
  Decision (2026-11-05): we will re-align their FASTQ on GRCh38 rather than lift over, because
  liftover silently drops variants in regions that changed between builds.
* Our earlier in-house BAMs (`*.sorted.bam`): GRCh38 and identical contigs, but **no read group and no
  index**, and no duplicate marking. They will be regenerated by the Phase 3 pipeline.

## 3. What are ALT contigs, and why does our reference warn about them?

The human genome is not one sequence. In some regions people carry very different versions
(**haplotypes**) of the same stretch of DNA — the classic example is the HLA region on chr6, also KIR on
chr19, and a few hundred other places. GRCh38 represents the main version on the chromosome itself
(the *primary assembly*) and the alternative versions as separate small sequences called **ALT
contigs** (`chr6_GL000250v2_alt`, …). Our `hg38.fa` contains **261** of them.

The problem: an ALT contig is ~99 % identical to the primary region it belongs to. When a read comes
from that region, BWA finds two equally good places (primary + ALT). An aligner that does not know they
are "the same place" concludes the read is ambiguous and gives it **mapping quality (MAPQ) 0**.
Variant callers ignore MAPQ-0 reads, so variants there are **missed (false negatives)**, and
coverage looks artificially low.

There are three standard fixes:

1. **ALT-aware alignment** — give BWA a `hg38.fa.alt` file describing how each ALT maps to the primary
   assembly; BWA then keeps MAPQ on the primary alignment. (Requires the `.alt` file; not present.)
2. **No-ALT analysis set** — use a reference with the ALT contigs removed (what GATK/Broad and most
   germline pipelines use).

3. **ALT masking (DRAGEN's method)** — keep all contigs, but replace the parts of ALT contigs that duplicate
   the primary assembly with `N`. A read can then only match the primary chromosome, so it keeps its MAPQ.
   The non-duplicated parts of ALT, decoy and HLA contigs remain and "catch" reads that truly belong there.

**Decision (2026-11-05):** stay on `hg38.fa` for now and document the limitation.

**Update (2026-11-18): option 3 implemented** as reference **`hg38_dragen_masked`** (Settings → References).
- Source: 1000 Genomes `GRCh38_full_analysis_set_plus_decoy_hla.fa` (the same base FASTA DRAGEN uses; its
  3,366 contigs are identical in name, order and length to the DRAGEN BAM from the provider). All 3,366
  sequence MD5s were checked against the published dictionary after download.
- Mask: Illumina's public `hg38_alt_mask.bed` (DRAGMAP GitHub), 2,907 intervals, 100.7 Mb in 786 ALT/HLA
  contigs. **No primary chromosome is changed** (checked by MD5).
- The chrY pseudo-autosomal regions are already N in this FASTA, which also removes the PAR limitation.
- Built with `scripts/build_masked_reference.sh` (bedtools maskfasta → samtools faidx/dict → bwa index,
  ~1 h). Provenance (URLs, SHA-256, tool versions) is in `<fasta>.masking.json`; the app's reference check
  reads a sample of the masked intervals back from the FASTA and refuses the reference if they are not N.
- The old `hg38.fa` is unchanged and still the default; choose the reference per run.
- Result on SAMPLE_A: see BAM_PROCESSING.md §5 and VARIANT_CALLER_COMPARISON.md §9d.

**What masking is not:** it is not BWA's ALT-aware mode (option 1). Reads are not assigned to ALT haplotypes,
so HLA typing or haplotype-specific analysis still needs dedicated tools.

**A no-download alternative** (option 2, not used): a no-ALT reference can be built
*locally* from the existing file, without touching it:
```bash
# list primary + random + chrUn contigs (everything except *_alt), then extract them to a NEW file
grep -v '_alt' ~/reference_genome/hg38.fa.fai | cut -f1 > noalt.contigs
samtools faidx ~/reference_genome/hg38.fa -r noalt.contigs > hg38_noalt.fa   # ~3.1 GB
samtools faidx hg38_noalt.fa
bwa index hg38_noalt.fa              # ~1 h, ~5 GB RAM, ~5 GB disk
gatk CreateSequenceDictionary -R hg38_noalt.fa
```
It would then be registered as a second reference in **Settings** and compared against the current one
on the same sample. This is a scientific change, so it will only be done with your agreement.

**Impact on comparisons with DRAGEN:** DRAGEN's hg38 reference is ALT-aware/masked and includes decoys,
so in ALT/decoy-related regions our BAM will show lower MAPQ and depth than the external BAM. The
comparison module (Phase 5) will report these regions separately instead of counting them as errors.

## 4. Glossary (growing)

| Term | Meaning |
|---|---|
| FASTQ | Raw reads: 4 lines per read (name, sequence, `+`, qualities). |
| Phred quality | Q = −10·log10(P_error). Q30 = 1 error in 1,000 bases. Encoded as ASCII char − 33. NovaSeq X uses only a few *binned* values (`#`, `*`, `9`, `I` = Q2, Q9, Q24, Q40). |
| Paired-end | Each DNA fragment is read from both ends: R1 and R2. Mates are in the same order in both files. |
| SAM/BAM | Aligned reads. BAM = compressed SAM. Header: `@SQ` (reference contigs), `@RG` (read groups), `@PG` (programs that produced it). |
| Read group (`@RG`) | Labels reads by sample (SM), library (LB), platform (PL), lane/unit (PU). GATK requires it. |
| MAPQ | Mapping quality: confidence the read is placed correctly. 60 = unique, 0 = multiple equally good places. |
| Checksum (SHA-256) | A 64-character fingerprint of a file's content. Any change to the file changes it. |
| Genome build | The version of the reference assembly (GRCh37/hg19 vs GRCh38/hg38). Coordinates differ between builds. |
| Adapter | Synthetic sequence ligated to DNA fragments; read into when the insert is shorter than the read. Must be trimmed. |
| Soft filter | A FILTER label on a VCF record (e.g. `LowDP`); the record is kept. A *hard* filter deletes it. |
| Concordance | Agreement between call sets: *allele* (same CHROM/POS/REF/ALT) or *genotype* (also same 0/1 vs 1/1). |
| Truth set | Variants of a reference sample (e.g. GIAB HG002) known with high confidence, plus the regions where that knowledge is reliable. Needed to measure precision/sensitivity. |
| Precision / sensitivity / F1 | TP/(TP+FP) · TP/(TP+FN) · their harmonic mean. |
| VAF | Variant allele fraction: ALT reads / (REF+ALT reads). Germline: ~0.5 het, ~1.0 hom. |
| Strand bias | ALT reads only on one strand — a typical artefact signature. |
| ALT contig | Alternative haplotype sequence of a region (e.g. MHC) included in GRCh38; causes MAPQ 0 without ALT-aware alignment. |
| Insert size | Length of the sequenced DNA fragment (between the adapters). |
| Duplicate (PCR/optical) | Multiple reads from the same original fragment. Flagged 0x400, ignored by callers. |
| Coordinate-sorted / index | Reads ordered by position; the `.bai` index allows jumping to a region. |
| Target BED / padding | Capture-kit regions (0-based, half-open intervals); padding extends them for calling. |
| Coverage / depth | Number of (non-duplicate, MAPQ ≥ 20) reads over a base. "% ≥ 20×" is the key exome QC metric. |
| Genotype (GT) | 0/1 heterozygous, 1/1 homozygous alternate, 0/0 reference. |
| Ti/Tv | Transitions / transversions; ~2.0-2.1 genome, ~2.6-3.3 exome for true germline SNVs. |
| Normalisation | Left-aligning and splitting variants so equal variants are written identically. |
| SNV / indel / MNP | Single-nucleotide variant / insertion-deletion / multi-nucleotide (adjacent) change. |
